# Руководство пользователя

## Вход в панель

1. Откройте публичный HTTPS-адрес панели.
2. Введите `ROUTER_SUPPORT_ENGINEER_TOKEN`.
3. После проверки сервер создаст подписанную защищённую HttpOnly-cookie на 12 часов.

При неверном токене сервер отвечает `403` и не отдаёт основной HTML, JavaScript и CSS
панели. Сам инженерный токен в браузере не сохраняется. После входа в шапке панели
показывается отдельный токен подключения OpenWrt с кнопкой копирования.

Панель запрещает браузерное кэширование защищённых файлов. После переустановки сервера
устаревшая cookie автоматически удаляется, и пользователь снова попадает на страницу
ввода инженерного токена.

Получить токен может администратор VPS:

```sh
grep '^ROUTER_SUPPORT_ENGINEER_TOKEN=' /etc/router-support/backend.env
```

## Установка агента OpenWrt

Установщик показывает этапы загрузки, подготовки устройства, регистрации и запуска
службы. Успешное завершение означает, что сервер подтвердил не только heartbeat, но и
reverse SSH-туннель. Итоговая строка имеет вид
`Status: online (heartbeat and SSH tunnel verified)`.

Перед регистрацией установщик синхронизирует часы роутера по заголовку времени из
проверенного HTTPS-соединения с GitHub. Это необходимо для новых устройств с неверной
датой, на которых TLS иначе отвечает `certificate is not yet valid`. Проверка TLS при
этом не отключается. Если GitHub-вариант недоступен, используется ограниченная по
времени попытка NTP и выводится предупреждение при неудаче.

Если туннель не поднялся за 30 секунд, установщик выводит последние сообщения агента
и не сообщает об успешной установке. После устранения указанной причины проверку можно
повторить:

```sh
/etc/init.d/router-support restart
/usr/sbin/router-support verify
```

## Список устройств

Карточка показывает:

- hostname и модель;
- версию OpenWrt и UUID;
- LAN/base MAC-адрес;
- внешний IP, приблизительные страну/город, ISP и ASN;
- назначенный reverse SSH-порт;
- время последнего heartbeat;
- отдельные состояния heartbeat и SSH-туннеля;
- локальные заметки инженера.

Статус «Онлайн» означает, что heartbeat свежий и reverse SSH-туннель действительно
подключён. «Нет SSH-туннеля» означает, что агент отправляет heartbeat, но поддержка
через SSH недоступна. Поле поиска также учитывает IP, ISP, город и заметки.

Геолокация IP является справочной: VPN, CGNAT и мобильные сети могут показывать город
или регион провайдера, а не точку установки роутера.

## Заметки

Введите адрес установки, контакт или особенности устройства и нажмите «Сохранить
заметки». Они хранятся только в серверной SQLite и не отправляются на OpenWrt.

## Журнал подключений

Кнопка «Журнал подключений» открывает overlay, который автоматически обновляется раз в
пять секунд. В нём сохраняются последние 5000 событий: регистрация, изменение внешнего
IP, переходы между online/offline и состоянием без туннеля, запуск и обрыв support SSH,
а также открытие и закрытие веб-терминала. UUID указан рядом с каждым событием.

Системный журнал с дополнительными техническими сообщениями остаётся доступен на VPS:

```sh
journalctl -u router-support -n 200 --no-pager
```

## Переименование

Нажмите значок карандаша рядом с hostname. Допустимы латинские буквы, цифры и дефис,
длина — до 63 символов. Изменение применяется на самом OpenWrt через UCI и затем
отображается в базе.

## Начало поддержки

Нажмите «Начать поддержку». Сервер:

1. проверит online-состояние и права;
2. создаст временную сессию;
3. откроет локальные SSH-форварды на VPS;
4. выдаст защищённые ссылки сервисов.

Доступны:

- **LuCI** — интерфейс OpenWrt;
- **V2RayA** — если сервис включён на роутере;
- **SSH** — интерактивный root-терминал в браузере;
- **Web App** — показывается только после включения сервиса на порту `2018`.

Сервисные ссылки получают HttpOnly cookie через одноразовый секрет во fragment URL.
Fragment не передаётся серверу и не попадает в access log.

## Веб-SSH

Кнопка SSH существует только в активной support-сессии. Терминал поддерживает обычный
ввод, Enter, Tab, Backspace, стрелки, вставку и `Ctrl+C`. Ticket одноразовый и действует
30 секунд. Терминал имеет root-доступ — выполняйте команды осознанно.

## Завершение поддержки

Нажмите «Завершить поддержку». Сервер уничтожит SSH-процесс, терминалы и локальные
форварды. Старые ссылки сразу начнут возвращать `403`. Без ручного завершения сессия
закроется по таймауту, по умолчанию через один час.

Если первый браузер был закрыт или потерял сеть, откройте панель с другого устройства.
Панель загрузит активную сессию с сервера и покажет «Завершить занятую сессию». Эта
кнопка доступна даже если роутер успел перейти в offline, и освобождает подключение без
перезапуска `router-support.service`. Секретные ссылки старой сессии восстановить во
втором браузере нельзя, поэтому там показывается только управление сессией и SSH.

## Удаление устройства с OpenWrt

Кнопка «Удалить подключение» в карточке завершает активную поддержку, при доступном
туннеле останавливает серверный агент на OpenWrt, удаляет историю устройства из SQLite
и отзывает его ключ из `authorized_keys`. Для возврата устройства после этого запустите
OpenWrt-bootstrap и выберите `Configure a new server connection`.

Отдельно удалить сам агент и его локальные файлы можно непосредственно на OpenWrt.

Удаление выполняет администратор. Обычный режим сохраняет идентичность для повторной
установки, а `--purge` удаляет её полностью. Команды и последствия описаны в
[руководстве эксплуатации](OPERATIONS.md#удаление-агента-с-роутера).
